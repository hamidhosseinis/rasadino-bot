# دانلود یوتیوب (عمومی) — آماده اتصال

**وضعیت:** فقط شاخه آزمایشی؛ انتشار Worker اصلی تا زمان اتصال سرویس و آزمون ارسال واقعی انجام نشود.

- دکمه **«📥 دانلود»** در منوی اصلی تمام کاربران چت خصوصی نمایش داده می‌شود؛ با لمس آن بات درخواست ارسال لینک می‌دهد. دستور `/download` نیز همین پیام را نمایش می‌دهد.
- **بدون لمس دکمه یا استفاده از دستور هم کار می‌کند:** ارسال لینک مستقیم و معتبر ویدئوی یوتیوب در هر زمان، حتی در نخستین پیام، درخواست دریافت فایل را ثبت می‌کند.
- تشخیص خودکار در ابتدای پردازش پیام، حتی اگر کاربر قبلاً بخش رصد موزیک را باز کرده باشد؛ ورودی: پیوند ویدئوی تکی از YouTube، `youtu.be`، Shorts یا Live ضبط‌شده؛ پلی‌لیست‌ها پذیرفته نمی‌شوند. سایر متن‌ها با رفتار قبلی مدیریت می‌شوند.
- خروجی: فایل ویدئویی MP4 به تلگرام، **نه لینک دانلود**؛ سقف اولیه ۴۵ MiB، مدت حداکثر ۲۰ دقیقه و کیفیت ترجیحی ۴۸۰p.
- پردازش دریافت و آپلود خارج از Cloudflare Workers انجام می‌شود. فایل موقت پس از پردازش حذف می‌شود؛ **هیچ سرویس عمومی ناشناس** برای دریافت فایل استفاده نمی‌شود.
- محدودیت هر کاربر: حداکثر ۳ درخواست پذیرفته‌شده در روز (UTC)، فاصله ۶۰ ثانیه بین درخواست‌های موفق؛ سرویس پردازشگر به‌صورت پیش‌فرض تنها یک درخواست همزمان پردازش می‌کند. شمارش KV برای استفاده ابتدایی است و تضمین ضدسوءاستفاده اتمیک نیست.
- دانلود فقط برای محتوایی که حق دریافت و نگهداری آن را دارید؛ محدودیت‌های YouTube و حقوق نشر رعایت شود. DRM دور زده نمی‌شود.

## راه‌اندازی مستقل پردازشگر

بر روی یک میزبان Python/Docker قابل دسترس با HTTPS، پوشه `services/youtube-downloader` را اجرا کنید؛ نمونه:

```bash
docker build -t rasadino-youtube services/youtube-downloader
docker run --rm -p 8080:8080 \
  -e BOT_TOKEN='<telegram-token>' \
  -e DOWNLOAD_API_KEY='<long-random-shared-secret>' \
  rasadino-youtube
```

HTTPS با reverse proxy معتبر ضروری است. توکن‌ها/شناسه‌ها را در GitHub یا لاگ ثبت نکنید. نمونه فوق صرفاً نمایشی است؛ برای سرور واقعی از secret manager به جای قرار دادن مقدارها در خط فرمان استفاده کنید.

سپس در **Cloudflare Worker** دو secret تنظیم شود:

- `YOUTUBE_DOWNLOAD_SERVICE_URL`: نشانی کامل HTTPS، پایان‌یافته به `/jobs`.
- `YOUTUBE_DOWNLOAD_API_KEY`: دقیقاً برابر `DOWNLOAD_API_KEY` پردازشگر.

`BOT_TOKEN` فعلی در Worker دست‌نخورده باقی می‌ماند. سرویس پردازشگر با **کلید مشترک محرمانه** فقط درخواست‌هایی را می‌پذیرد که Worker تأییدشده بفرستد؛ محدودیت مالک حذف شده است. هیچ راز یا توکنی در مخزن عمومی قرار نگیرد.

## ترتیب انتشار ایمن

۱. بررسی CI، آزمون نمایش عمومی دکمه و ارسال لینک بعد از لمس آن، تشخیص خودکار لینک کاربر تازه‌وارد بدون دکمه، حفظ عملکرد موزیک و سایر فرمان‌ها و کنترل سهمیه.
۲. اجرای سرویس جانبی، صحت `GET /health` و اعتبارسنجی HTTPS/کلید مخفی.
۳. آزمون دریافت فایل واقعی کوچک و **دارای مجوز** در دو چت مستقل؛ ارزیابی صف، مصرف منابع و سقف همزمانی.
۴. گرفتن نسخه برگشت از Worker v30، انتشار تدریجی نسخه جدید با حفظ bindings و Cron.
۵. بررسی منوی سایر کاربران و اینکه قیمت‌ها/موسیقی/خبر/هواشناسی تغییر نکرده‌اند.

**توجه:** پذیرش HTTP 202 فقط به معنای ثبت درخواست است؛ موفقیت دانلود و ارسال فقط با دریافت واقعی فایل در تلگرام تأیید می‌شود. تا قبل از راه‌اندازی مستقل دانلودر و تنظیم Secretها در Worker، این PR نباید به‌عنوان یک قابلیت عملیاتی منتشر شود.
